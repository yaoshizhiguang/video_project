# AI Video Generation Methodology

## 用途

记录《咕咕嘎嘎企鹅》项目中每次失败、返工和用户反馈沉淀出的通用方法论。  
后续生成其他集、其他段落或其他角色视频时，先查本文件，再写 prompt 或生成关键帧。

## 总原则

- 每次失败不能只记录结果，要总结成可复用规则。
- 每条规则都要回答三个问题：为什么失败、以后怎么做、生成前检查什么。
- 方法论优先服务后续生产流程，不只服务当前这一张图或这一段视频。
- 如果方法论变化影响 prompt，必须同步更新对应 prompt 文件。
- 已进入可用状态的 prompt 不直接覆盖；后续修改必须另存为新版本文件，并在旧文件中保留原内容。
- 如果方法论来自图片/视频生成反馈，必须同步更新 `generation_log.csv` 和 `generation_log.html`。

## 失败复盘格式

```text
### YYYY-MM-DD 主题

失败现象：
- 生成结果具体哪里不对。

根因判断：
- prompt、参考图、工作流或资产结构哪里导致了问题。

沉淀方法论：
- 后续所有类似任务应该遵循的规则。

生成前检查项：
- 进入下一轮生成前必须逐条确认的 checklist。

影响文件：
- 相关 prompt、日志、资产或目录。
```

## Prompt 输出格式规则

- 从 2026-05-18 起，交付给用户直接使用的视频生成 prompt 默认使用中文，除非用户明确要求英文。
- 后续提供给生成工具使用的 prompt，优先写成一个可直接复制的完整文本块。
- 负向约束不要单独留给用户二次拼接，必须直接写在同一个文本块末尾，并以 `Avoid:` 开头。
- 文档标题可以写成“一键复制 Prompt（正向内容 + Avoid 负向约束）”，让用户知道 `Avoid:` 之后是负向内容。
- 如果某个生成工具明确支持独立负向输入框，可以额外提供拆分版；但默认交付必须先给一体化可复制版。
- `Avoid:` 中也不能出现会误导模型的未出场人物名；如果需要禁止后续主角提前出现，用“later hero character visible”或具体视觉元素替代。

## Prompt 注意力预算规则

- 视频模型通常会更精准执行 prompt 前 200-300 字，后面的注意力会逐渐分散。
- Prompt 开头必须放最高优先级、最可执行的画面指令：参考图用途、时长画幅、风格、镜头、背景锁定、核心动作机制、绝对禁止的剧情方向。
- 不要在开头写解释性、总结性或流程管理句，例如“本段只表现……”“本版重点修正……”。这些内容应留在文档说明，不进入一键复制 prompt 的正向正文。
- 正向 prompt 中不要写“如果有 X”“可以有 X”“只允许 X 最后出现”这类带条件的危险元素；模型可能只抓住 X 并生成它。
- 对高风险元素，正向正文应完全避免提及，必要时只放在 `Avoid:` 中。例如不想要漂浮冰晶，就不要在正向正文写“如果有冰晶，只能……”，而应改写为“粉尘粒子、霜雾、薄雾光带”等替代元素。
- 风格词如果是关键稳定器，例如“皮克斯风格3D动画”，应放在前 200 字内，而不是放在后段说明里。

生成前检查项：

- 一键复制 prompt 的前 200-300 字是否已经包含时长、画幅、风格、镜头、背景锁定和核心动作机制。
- 正向正文是否出现了不想生成的高风险元素名。
- 是否把解释性规则写进文档说明，而不是塞进 prompt 正文。
- `Avoid:` 是否承担禁止职责，正向正文是否只描述想要的画面。

## 中心腹部漩涡生成规则

- 雪怪生成和攻击蓄能必须以“肚子中心漩涡”为唯一核心，而不是整体龙卷风、垂直旋风柱或怪物从风暴里走出来。
- 成功写法优先强调：固定背景、固定广角、所有冰粒子/雪花/雾气/云朵都动态汇聚到中心腹部漩涡，形成清晰螺旋轨迹。
- 生成阶段：空中先出现大量微小粉尘状冰粒子，像冰蓝色星尘一样带柔和发光拖尾，再被漩涡主动吸收，从内向外逐层聚合身体。
- 攻击阶段：发射射线前，腹部漩涡加速旋转、变亮、聚集能量；射线发出后，漩涡逐渐变淡，回到主参考图中的常态漩涡。
- 视频 prompt 中必须明确“无整体龙卷风”“无怪物悠闲走路”“无攻击提前出现”“中央大冰山不变形不变矮”。

生成前检查项：

- prompt 是否写明背景元素全程完全不变，包括中央大冰山高度、形状、位置。
- prompt 是否写明所有特效都汇聚到中心腹部漩涡，而不是大风暴或龙卷风。
- prompt 是否写明粉尘状冰粒子、柔和冰蓝色发光拖尾、螺旋轨迹。
- prompt 是否写明怪物从漩涡由内向外逐层聚合形成。
- 如果是攻击段，是否写明漩涡先聚能再发射，发射后漩涡变淡。

## 冰雪魔法特效去廉价冰晶规则

- 不要用具体动画公司、电影、系列或 IP 名称描述风格；把想要的效果拆成通用视觉语言，例如“高端家庭动画电影质感、柔和折射、半透明冰雾、粉尘状冰粒子、薄雾光带、流体螺旋运动”。
- “ice crystals / crystal shards / floating blue ice crystals / embedded glowing ice crystals”等词容易触发大块菱形冰晶、悬浮水晶、尖锐冰片和廉价闪光碎片；剧情镜头里应谨慎使用。
- 空中特效主体应写成：细冰粉、霜雾微粒、半透明雪粉、柔和冰蓝光带、发光冰雾、流体般螺旋轨迹。
- 如果需要雪怪身上的冰装饰，只允许作为“附着在怪物身体表面的少量小型冰质点缀”，不能漂浮在空中，也不能像最后雪怪身上插着的硬质冰晶提前出现。
- 破冰或攻击命中时可以出现真实碎冰，但必须限定在“撞击点附近的可读冰块和雪粉”，不要让碎冰变成全画面随机漂浮水晶。

生成前检查项：

- prompt 是否出现了 `ice crystals`、`crystal shards`、`floating crystals`、`sparkly debris` 这类高风险词。
- 是否明确禁止菱形冰晶、巨大漂浮冰晶、悬浮水晶、硬质冰片、廉价粒子闪光。
- 是否把冰雪魔法拆成雾、粉、光、折射和流体运动，而不是硬质水晶道具。
- 如果有冰块破碎，是否只发生在攻击命中点，而不是空中到处漂浮。
- 是否避免使用具体动画品牌或电影名称来描述风格。

## Storyboard-First 视频输入规则

- 后续视频生成默认采用“角色/怪物设定图 + 单张故事板图 + 一镜到底 prompt”的输入结构。
- 不再把多张独立关键帧同时上传给视频模型作为同一段视频的直接参考。
- 多张关键帧直接上传给视频模型时，模型容易误以为用户要把这些图当作视频剪辑、幻灯片或多段素材拼接，而不是生成同一个镜头里的连续动态。
- 关键帧仍然要生成，但用途是内部导演板：确定剧情阶段、构图锚点、角色状态、VFX 递进和 prompt 语言。
- 交给视频模型的故事板图必须把多个阶段整合进一张图，并用极短 caption 标明时间顺序；故事板只能帮助模型理解阶段、构图和角色/物体状态。
- 如果不是动态故事板，而是静态布局参考图，必须明确写清它只用于背景元素位置、动物初始位置、道具位置和怪物最终站位；不能让模型把它理解成中间关键帧或剪辑素材。
- 不能指望视频模型自动从故事板理解动态过程。故事板中的箭头、分格、阶段图不会自动变成正确运动。
- 所有动态变化都必须在视频 prompt 中写清楚，包括时间轴、运动方向、特效来源、能量流向、角色反应、物体位移、因果关系、起止状态和禁止出现的错误动态。
- 故事板 caption 只用于理解剧情，不应出现在最终视频里；视频 prompt 必须明确 `do not show storyboard panels, captions, gutters, or text`。
- 故事板要强调流程递进，而不是精确逐帧复刻；视频 prompt 必须写 `convert the storyboard into one smooth continuous scene`。
- 对一镜到底段落，故事板必须服务连续运动：同一场景、稳定地平线、核心道具/角色锚点、自然角色朝向变化、无突变瞬移。
- 后续视频 prompt 默认中文，除非用户明确要求英文；中文 prompt 更利于当前工作流中准确描述特效、因果和约束。

生成前检查项：

- 是否只上传必要设定图和一张故事板图，而不是 A/B/C/D/E 多张关键帧。
- 如果上传的是静态布局参考图，prompt 是否明确它只用于场景布局和最终站位。
- 故事板是否清楚标明 3-5 个阶段，而不是塞太多信息。
- 每个阶段是否自然递进，尤其角色朝向、情绪、动作是否符合时间线。
- prompt 是否逐秒写清楚动态，而不是只写“参考故事板”。
- prompt 是否写清楚特效怎么产生、从哪里来、向哪里去、何时增强、何时消散。
- prompt 是否写清楚故事板只作为参考，不要显示分格、白边、编号、caption 或文字。
- 是否避免故事板自身变成视频画面：分格、白边、caption、编号、拼贴布局都必须被禁止出现在视频里。
- prompt 是否明确禁止 hard cut、fade、dissolve、slideshow transition、jumping between panels。
- prompt 是否明确要求把故事板转化为同一镜头中的连续变化。

## 2026-05-16 角色参考图跑成真实企鹅

失败现象：
- AI 把咕咕嘎嘎生成成真实企鹅，而不是参考图中的企鹅外套 Q 版少女 IP。

根因判断：
- `penguin`、`Antarctic penguin`、`soft feathers` 等词过强，压过了参考图身份。
- 负向词里的 `human body` 误伤了参考图中的少女人脸、黑短发、蓝发卡等关键身份。

沉淀方法论：
- 角色 prompt 必须 reference-first：先说“严格保留参考图主体”，再描述微调。
- 不能用物种词重新定义角色；如果参考图本质是 IP 角色，必须锁定 IP 身份，而不是动物物种。
- 负向词不能误伤参考图已有特征。

生成前检查项：
- 是否明确写了 `do not redesign the character`。
- 是否保留少女人脸、黑短发、蓝色发卡、企鹅 hood、红围巾。
- 是否删除会把角色拉向真实动物的强触发词。

## 2026-05-17 雪怪设计方向发散

失败现象：
- 雪怪多轮生成后出现雪人王、老人脸、胡子、拳头、人形巨怪、灾害墙等偏离。
- 部分版本画质更酷，但不符合第一集剧情功能。

根因判断：
- prompt 中的 `king`、`crown`、`boss`、`storm titan`、`wall` 等词容易把设计推向新概念。
- 只追求惊艳感会牺牲剧情功能：雪怪必须能被雪球包住并变成巨大雪人。

沉淀方法论：
- 已选主参考后，不要继续重新发明角色，只做小幅强化。
- 怪物设计必须先满足剧情机制，再考虑吸睛度。
- 对反派角色要同时检查：识别度、尺度、可动画性、可被剧情机制处理。

生成前检查项：
- 是否以 `snowstorm_monster_primary_reference.png` 为最高优先级。
- 是否禁止老人脸、王冠、胡子、拳头、腿脚、人形巨人。
- 是否确认雪怪明显小于大型冰山和远山。
- 是否确认最终雪球可以包住雪怪。

影响文件：
- `02_prompts/monster/snowstorm_monster_design_spec_v001.md`
- `02_prompts/monster/snowstorm_monster_prompt_v010_v001_locked_refine.md`

## 2026-05-17 雪怪尺度失控

失败现象：
- 雪怪设定图把雪怪做成山脉级，甚至比雪山和大型冰山还大。

根因判断：
- `giant`、`massive`、`boss` 等词如果没有尺度锚点，会被模型理解成 kaiju / 山脉级怪物。
- 缺少“能被雪球包住”的剧情功能约束。

沉淀方法论：
- 所有怪物 prompt 必须提供相对尺度，而不是只写“巨大”。
- 比例约束要用剧情机制校验：能否被第 6 段雪球包成雪人。
- 尺度参考必须按生成用途分层：资产设定图可以包含主角、小动物、冰山、远山和最终雪球；剧情镜头 prompt 只能引用当前镜头中已经出场或允许出现的对象。
- 如果咕咕嘎嘎还没有出场，不能在该镜头 prompt 里写“雪怪约为咕咕嘎嘎高度的 8-12 倍”，否则模型可能把咕咕嘎嘎提前画进画面，或把隐藏角色当作构图锚点。

生成前检查项：
- 如果是资产比例图，可以写雪怪约为咕咕嘎嘎高度的 8-12 倍。
- 如果是咕咕嘎嘎未出场的剧情镜头，只用小企鹅、小海豹、鱼桶、中景冰山、远处雪山做比例锚点。
- 雪怪明显小于大型冰山和远处雪山。
- 最终雪球约为雪怪高度的 1.2-1.5 倍。
- prompt 中明确禁止 `mountain-sized monster`、`kaiju scale`、`monster larger than mountains`。

影响文件：
- `02_prompts/segments/ep001_asset_pack_prompt_v001.md`
- `03_keyframes/episode_001/ep001_keyframe_prompts_v001.md`

## 2026-05-17 禁止用未出场人物做提示词锚点

失败现象：
- 在雪怪出场阶段，prompt 或方法论里提到“雪怪约为咕咕嘎嘎高度的 8-12 倍”，但咕咕嘎嘎此时还没有出场。

根因判断：
- AI 生成模型会把 prompt 中出现的人物名当作需要表现或参与构图的对象。
- 即使本意只是说明比例，未出场人物也可能被提前生成，造成剧情顺序错误和画面污染。

沉淀方法论：
- 剧情镜头 prompt 只能写该镜头已经出场、允许出场或画面中必须存在的对象。
- 未出场角色不能作为比例尺、动作参照、视线参照、背景虚化对象或构图锚点。
- 比例约束要改用当前画面内合法对象，例如小企鹅、小海豹、鱼桶、中景冰山、远山、水面边界。
- 只有资产设定图、比例 lineup 或全局 bible 可以同时列出未同场出现的角色做比例对照。

生成前检查项：
- prompt 中是否出现了当前镜头不该出现的人物名。
- 比例说明是否可以改成当前画面内的动物、道具、冰山或远山。
- 负向 prompt 是否明确禁止未出场角色提前出现。
- 如果只是方法论或设定说明，是否标明“仅限资产比例图，不用于剧情镜头 prompt”。

影响文件：
- `09_logs/video_generation_methodology.md`
- `03_keyframes/episode_001/ep001_keyframe_prompts_v003_progressive_monster_birth.md`
- `02_prompts/segments/ep001_segment01_progressive_birth_video_prompt_v003.md`

## 2026-05-17 动作图不是视频动作控制核心

失败现象：
- 多格雪怪动作图没有被视频模型有效参考。
- 模型容易忽略某个具体动作，或把整张图理解成拼贴/分屏。

根因判断：
- 多格 pose sheet 对图生视频的动作约束弱。
- 同一张图里包含太多动作状态，会增加输入噪声。

沉淀方法论：
- 动作图不作为 AI 视频生成核心必备资产，只作为可选参考。
- 视频动作控制优先使用：母场景、连续关键帧、时间轴动作描述、因果链、VFX 分层。
- 如果确实需要姿势参考，生成单动作干净 pose reference，而不是上传多格动作合集。

生成前检查项：
- 是否真的需要上传动作图。
- 如果上传，是否说明“仅作外观/局部姿态参考，不是分屏布局”。
- 是否已有清楚的时间轴动作描述。

影响文件：
- `09_logs/decision_log.md`
- `02_prompts/segments/ep001_segment01_one_shot_video_prompt_v002.md`

## 2026-05-17 多关键帧背景不一致导致硬切

失败现象：
- 第一版视频在 `KF01A/KF01B/KF01C` 节点间生硬切换，像三张独立海报拼接。

根因判断：
- 三张关键帧背景、天空、冰山布局、镜头机位都不一致。
- 视频模型无法在不同场景之间自然补间，只能硬切或重构画面。

沉淀方法论：
- 连续视频关键帧必须来自同一个背景母版。
- 先锁定母场景，再用图生图 / variation 派生后续状态。
- 关键帧之间只允许事件层变化，不允许场景结构变化。

生成前检查项：
- 机位是否一致。
- 地平线是否一致。
- 中景冰山位置和形状是否一致。
- 远山轮廓是否一致。
- 前景冰面、水面边界、鱼桶位置是否一致。
- 每张图是否像同一镜头的不同时间点。

## 2026-05-17 雪怪出场太结果导向

失败现象：
- 雪怪诞生画面像“雪怪已经站在那里”，缺少风暴、雪云、冰晶逐步聚合的过程。

根因判断：
- 关键帧跨度过大，从平静南极直接跳到完整雪怪。
- prompt 描述结果多，描述生成过程少。

沉淀方法论：
- 复杂出场要拆成渐进式状态，不要只给结果图。
- 元素生成式出场要有清楚层次：风 -> 雪云 -> 冰晶 -> 眼睛 -> 云洞嘴 -> 身体轮廓 -> 雪雾基座。
- 最吸睛的不是“完整怪物站好”，而是“人格特征在自然灾害中出现”的瞬间。

生成前检查项：
- 是否有“异变开始”帧。
- 是否有“蓝眼先出现”的聚合帧。
- 是否有“半成型、下半身仍是雪雾”的过渡帧。
- 是否避免直接生成完整站立怪物。

影响文件：
- `03_keyframes/episode_001/ep001_keyframe_prompts_v003_progressive_monster_birth.md`
- `02_prompts/segments/ep001_segment01_progressive_birth_video_prompt_v003.md`

## 2026-05-17 雪怪生产设定图 prompt 成功因素

成功现象：
- 新一版雪怪 model sheet 更像可用生产资产：正面、侧面、背面、三分之四视图、眼睛/嘴/冰晶/材质细节和比例 lineup 都更清晰。
- 雪怪保持了主参考的蓝眼、云洞嘴、腹部风暴旋涡、冰晶和宽雪雾底座，同时减少了人形巨怪、老人脸、手指、腿脚和过度毛绒感。

根因判断：
- prompt 明确区分了 model sheet、action sheet、cinematic scene 和 redesign，任务边界更清楚。
- `front view is the primary identity anchor` 让主视图最接近参考，避免多视图把角色重新设计。
- shape language、material language、face language 分层写得很具体，模型知道哪些能变、哪些不能变。
- scale comparison 直接服务剧情功能：雪怪要大于动物，但小于大冰山，并能被最终雪球包住。

沉淀方法论：
- 生产设定图 prompt 要先定义资产类型，再定义身份锁定，再分层写形体、材质、脸部、尺度和版式。
- 对软体/云雾怪物，要明确“侧面团块不是手臂”“底部雪雾不是双腿”，否则模型会自动补人形结构。
- 材质描述要同时写外层颜色和内部结构，避免变成纯白棉花、毛绒玩具或棉花糖。
- 比例 lineup 只适合资产设定图；剧情镜头不能照搬其中未出场角色的比例描述。

生成前检查项：
- 是否明确 `not an action sheet, not a cinematic scene, and not a redesign`。
- 是否指定 front view 为 identity anchor。
- 是否分层写 shape language、material language、face language。
- 是否禁止 articulated arms、fingers、split legs、feet。
- 是否包含剧情机制校验：最终雪球能包住雪怪。

影响文件：
- `02_prompts/prompt_library.md` 的“单独生成：雪怪设定图（已选定 v003）”
- `00_references/monster/images/model_sheets/ep001_snowstorm_monster_model_sheet_v003_production.png`

## 2026-05-17 渐进式出场节点不能过早成型

失败现象：
- 用于“异变开始 / 聚合中”的画面已经把雪怪完整画出来，虽然正面构图和压迫感很好，但时间轴上跳过了“蓝眼先出现、风雪聚合、身体逐步成型”的过程。

根因判断：
- prompt 对“聚合中”的完成度约束还不够硬，只写了 `not fully formed`，但没有明确禁止完整头部、完整圆身体、手臂和完整轮廓。
- 生成模型容易把雪怪主参考和“dramatic birth moment”理解为直接展示完整怪物。

沉淀方法论：
- 渐进式出场要把每个节点的“允许出现什么”和“绝对不能出现什么”写清楚。
- 聚合中 Shot C 的第一可读特征应是蓝色眼睛，身体仍是雪云、风、冰晶、雪雾的未完成聚合体。
- 如果某张图很好看但成型过早，不要丢掉，可降级为后续 reveal 的构图参考，而不是继续当作当前节点使用。

生成前检查项：
- Shot C 是否只有蓝眼睛最清楚。
- 是否没有完整头部、完整圆身体、清晰手臂、完整嘴巴和完整怪物轮廓。
- 是否还能看出风、雪雾、冰晶正在聚合，而不是雪怪已经站好。
- 成型过早的图是否已经标记为后续 Shot E/D 参考，而不是当前选中帧。

影响文件：
- `03_keyframes/episode_001/ep001_keyframe_prompts_v003_progressive_monster_birth.md`
- `02_prompts/segments/ep001_segment01_progressive_birth_video_prompt_v003.md`
- `03_keyframes/episode_001/KF01E_monster_reveal_attack_ready/ep001_KF01E_front_camera_reference_v001.png`

## 2026-05-17 切换镜头视角必须整组重建

失败现象：
- 平静南极和异变开始是同一侧向场景体系，但后续参考图采用更正面的 Boss reveal 机位。如果直接混用，视频会从侧向环境突然切到正面环境。

根因判断：
- AI 视频模型对关键帧之间的大机位变化不擅长自然补间，会把它理解为换场景、硬切或重新生成环境。
- “正面视角更好”是镜头体系决策，不是单张图局部修改；一旦选择，就要从母版开始统一。

沉淀方法论：
- 发现更好的机位时，不要只替换中后段关键帧；先决定是否切换整组镜头体系。
- 如果切换，必须从 Shot A 母版开始重建，再用图生图派生 Shot B/C/D/E/F。
- 旧图可以作为内容节奏参考，新图作为 camera/framing reference，但不能混在同一连续视频关键帧链里直接使用。

生成前检查项：
- Shot A/B/C 是否是同一个相机方向。
- 中央冰山、地平线、远山、动物和鱼桶是否在相同位置关系中演化。
- 正面视角参考是否只作为构图参考，而不是提前引入完整雪怪。
- 是否避免右侧大冰山在所有镜头里抢走主要视觉焦点。

影响文件：
- `03_keyframes/episode_001/ep001_keyframe_prompts_v003_progressive_monster_birth.md`
- `02_prompts/segments/ep001_segment01_progressive_birth_video_prompt_v003.md`

## 后续工作流固定检查

每个新视频段落生成前，先确认：

- 是否有明确母场景或起始帧。
- 是否区分了不变层和变化层。
- 是否把复杂事件拆成足够多的递进状态。
- 是否明确角色/怪物主参考优先级。
- 是否有尺度锚点和剧情功能校验。
- 是否避免上传会增加噪声的多格动作图。
- 是否把失败复盘同步到本文件、`decision_log.md`、`generation_log.csv` 和 `generation_log.html`。
